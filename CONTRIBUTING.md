# 🤝 Contributing to Engineering Playbook

First off, **thank you** for taking the time to contribute! 🎉

This project is a community-driven collection of engineering knowledge. Whether you're fixing a typo, adding new notes, or suggesting a new topic — every contribution matters.

---

## 📋 How Can You Contribute?

### 📝 Add or Improve Notes
- Add notes in PDF, Markdown, or document format to the appropriate subject folder
- Improve existing content with better explanations, diagrams, or examples
- Fix typos, grammatical errors, or formatting issues

### 📁 Suggest New Topics
- Open an [Issue](../../issues) to suggest a new subject area or topic
- Provide a brief description of what should be covered

### 🐛 Report Issues
- Found a broken link or incorrect information? Open an [Issue](../../issues)

---

## 🚀 Getting Started

1. **Fork** this repository
2. **Clone** your fork:
   ```bash
   git clone https://github.com/YOUR_USERNAME/engineering-playbook.git
   ```
3. **Create a branch** for your changes:
   ```bash
   git checkout -b feature/add-new-topic
   ```
4. **Make your changes** — add notes, fix errors, improve formatting
5. **Commit** your changes:
   ```bash
   git commit -m "Add: [brief description of changes]"
   ```
6. **Push** to your fork:
   ```bash
   git push origin feature/add-new-topic
   ```
7. **Open a Pull Request** against the `main` branch

---

## 📐 Guidelines

### File Organization
- Place resources in the **correct subject folder** (e.g., DSA notes go in `DSA/`)
- If a folder doesn't exist for your topic, create one with a descriptive name
- Add a `README.md` to any new folder explaining its contents

### Naming Conventions
- Use **descriptive file names** (e.g., `Graph_Theory_Notes.pdf`, not `notes.pdf`)
- Folder names should use **PascalCase** or **snake_case** (e.g., `System_Design`)

### Commit Messages
Use clear, descriptive commit messages:
- `Add: Operating Systems scheduling notes`
- `Fix: Typo in System Design README`
- `Update: DBMS normalization section`
